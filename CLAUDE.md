# Working rules for this repo (read first)

## 1. Analyse code with the brain MCP, not file sweeps (mandatory)
- Start any analysis with the brain MCP tools: `brain_context` (one-shot), then `brain_search`, `brain_expand`, `brain_read`, and `brain_check <symbol>` before editing a symbol. Do not grep/ls the tree to find code.
- Run `brain_build` (or `brain build`) after edits so the index stays current. It is incremental.
- If the MCP tools are not available in a session, use the CLI with Node 24 first on PATH:
  `PATH=/Users/apple/.nvm/versions/node/v24.20.0/bin:$PATH brain context "<task>"`.
  The default shell `node` here is v18, which segfaults brain's native sqlite module (exit 139).
- Index location: `~/.brains/hr-assessment-backend-afe4aca1`. `BRAIN-INSTRUCTIONS.md` (git-ignored) is regenerated by `brain build`.

## 2. Read and write files with Claude's own tools (mandatory)
- Read with Read (use line ranges), write with Write, change with Edit.
- Do not read or write file content through shell scripts (`cat`, `sed`, `echo`, heredocs, inline `python -`). Use Bash only to run things (docker, pytest, git, brain).

## 3. Development-first policy
- Finish development first; keep tests lean. Run only the touched module's tests; run the full suite once at the end.
- Verify behaviour with live HTTP (curl/httpx/Playwright/Postman) and move on when APIs work.
- Use 2-3 parallel agents at a time, on disjoint directories, and put rules 1 and 2 in every agent brief.

## 4. Project facts
- Docker: `docker compose -f docker/docker-compose.yml run --rm api pytest tests/<module> -q`; `sh scripts/lint.sh`; `sh scripts/check_name.sh`.
- State and decisions: `docs/BUILD-STATE.md`, `docs/HANDOVER.md`. Live checks: `scripts/smoke_*.py`, `docs/smoke_report.md`.
